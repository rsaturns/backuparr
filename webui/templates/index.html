Service Authentication

Optional HTTP headers for apps behind an authenticating reverse proxy, used for connection tests, discovery, backups and restores. Each header goes to all apps or only the ones you pick. Values are stored encrypted.

Generate Basic authentication

Generate a Basic authentication value from a username and password, then apply it to a new or existing header.

Use the header your server expects: Authorization for HTTP Basic, Proxy-Authorization for a proxy that accepts it, or a custom name. Applying replaces the value of the row with that name; to add another row with the same name for different apps, add it with an empty value first.

Where headers are used

App API keys are still required. Each app's own authentication takes priority when it uses the same header name; use a separate header if your proxy supports one.

Each header goes to the URLs of the apps it applies to, including a restore target entered for one of them. The same name can be used for different apps, with a different value for each. Headers are not sent to backup storage or notification services. Redirects to another scheme, host or port are blocked.
